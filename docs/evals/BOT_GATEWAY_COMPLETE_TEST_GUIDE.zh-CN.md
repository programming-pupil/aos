# AOS Bot 网关完整测试手册

本文用于开源发布前，对 Bot 网关进行从零配置、权限隔离、身份绑定、会话连续性、能力路由、任务控制、主动通知、取消执行、故障恢复和多平台兼容性测试。

Bot 网关是 AOS 的外部交互入口。发布验收不能只验证“测试消息能发送”，必须证明以下完整链路成立：

```text
平台消息
→ AOS 收到入站事件
→ 识别外部用户并绑定 AOS 身份
→ 复用该用户在当前私聊中的超级助手 Session
→ 创建并执行真实任务
→ 在原私聊返回受理和最终结果
→ 用户可继续追问、查询、补充、审批或取消
→ 标准任务事件可主动通知到该用户
```

## 1. 测试结论标准

每轮测试记录以下结果：

- `PASS`：实际结果与预期一致，有页面、日志或任务记录证据。
- `FAIL`：功能错误、权限越界、消息丢失、重复执行或底层任务未停止。
- `BLOCKED`：由于缺少第三方账号、公网 Webhook 或平台审核而无法执行。
- `N/A`：本次发布明确不支持的能力，必须在发布说明中标注。

以下任一问题出现时禁止发布：

- 未绑定的社交账号可以访问 AOS 数据或创建任务。
- 普通用户可以查看或控制其他用户未共享的任务。
- 同一私聊的连续追问丢失上下文或错误串到其他用户。
- 页面显示取消成功，但模型流、工具或子任务仍继续运行。
- 同一个平台消息被重复执行。
- 任务完成但最终结果没有发送，且消息日志、任务中心没有明确失败原因。
- Token、Secret、API Key 或密码出现在页面、普通日志或出站消息中。

## 2. 当前产品边界

### 2.1 Bot、通道、身份和值守的关系

| 对象 | 作用 | 数据范围 | 是否必需 |
| --- | --- | --- | --- |
| 机器人 | 绑定超级助手、超级对抗、数据探索、代码开发等能力 | 租户共享 | 必需 |
| 通道 | 连接飞书、钉钉、企微、Slack 等平台 | 租户共享 | 必需 |
| 身份绑定 | 将平台用户映射为当前 AOS 用户 | 用户私有 | 首次使用必需 |
| 自动通知事件 | 将选定的标准任务事件推送到已绑定私聊 | 通道配置 + 用户绑定 | 可选 |
| 值守规则 | 按卡住时长、失败、等待输入等条件通知或请求动作 | 用户私有 | 可选 |

自然语言问答、创建任务、查询任务和取消自己的任务不要求配置值守规则。

### 2.2 会话规则

- 同一租户、同一 AOS 用户、同一平台、同一通道、同一外部会话复用一个超级助手 Session。
- 不同用户、不同通道或不同私聊不得复用 Session。
- Session 接近模型上下文上限时，AOS 应自动压缩历史并保留连续性，不应直接丢弃上下文。
- Session 已结束或无法复用时创建新 Session，新建 Session 的名称应为 `Bot`。
- 同一私聊中的每条消息仍会创建独立任务/Turn，但这些 Turn 归属于同一 Session。

### 2.3 管理员边界

- WebUI 任务接口支持管理员使用租户范围查看和控制租户任务。
- 当前 Bot 自然语言任务列表、相对指代和任务定位仍限制为绑定用户本人或已共享任务。
- 因此当前版本不能宣传“管理员通过 IM 无条件控制整个租户”。租户级 Bot 管理模式需要单独的显式指令、审计和高风险确认设计。

## 3. 测试环境

至少准备以下账号：

| 编号 | AOS 身份 | 页面权限 | 外部账号 |
| --- | --- | --- | --- |
| A | 管理员 | 全部权限 | 飞书账号 A |
| B | 普通成员 | `bot_agents:read`，无任务指挥中心菜单 | 飞书账号 B |
| C | 普通成员 | 无 `bot_agents:read` | 飞书账号 C |

至少准备：

- 一个可用的 AI Chat 模型。
- 两个不同的可用 AI Chat 模型，用于超级对抗。
- 一个测试数据源及最小查询权限，用于数据探索。
- 一个测试代码仓库和 Coding Agent，用于代码开发。
- 一个飞书企业自建应用。
- 可查看 AOS 服务日志的终端。

建议日志级别：

```bash
export RUST_LOG=web_server=info,agent_gateway=info,feishu_sdk=info,tower_http=info
```

测试期间禁止使用真实生产密钥、生产数据库和包含个人信息的消息。

## 4. 从零配置飞书

### BG-SETUP-001 创建机器人

1. 使用管理员进入“Bot 网关”。
2. 点击“新建机器人”。
3. 名称填写 `AOS 发布验收 Bot`。
4. 绑定“超级助手”，保持无前缀兜底。
5. 保存。

预期：

- 机器人列表只出现一条新记录。
- 能力显示“超级助手”。
- 启用状态正确。
- 不需要额外绑定“看门狗”能力才能查询或取消任务。

### BG-SETUP-002 创建飞书通道

1. 点击“新建通道”。
2. 选择上一步机器人和“飞书”。
3. 入站模式选择“自动”或“Stream 长连接”。
4. 填写飞书 App ID、App Secret。
5. 根据需要填写自定义机器人 Webhook；未填写时使用 OpenAPI。
6. 勾选测试所需自动通知事件。
7. 保存。

预期：

- 保存成功后自动进入“身份绑定”页签。
- 新通道被自动选中。
- 页面提示继续完成身份绑定。
- 服务日志最终出现飞书长连接处理器注册或连接成功信息。
- 页面不能回显 App Secret 明文。

### BG-SETUP-003 飞书开放平台配置

在飞书开放平台确认：

- 机器人能力已启用。
- 已订阅 `im.message.receive_v1`。
- 使用长连接接收事件。
- 应用具有接收消息和发送消息所需权限。
- 应用版本已发布到测试企业，测试用户可见。

预期：AOS 启动日志显示等待或已经接收 `im.message.receive_v1`，无持续重连错误。

## 5. 身份绑定闭环

### BG-ID-001 Bot 网关内完成绑定

1. 使用账号 A 打开“Bot 网关 → 身份绑定”。
2. 选择刚创建的飞书通道。
3. 点击“生成绑定码”。
4. 复制完整命令 `绑定 XXXXXXXX`。
5. 在飞书账号 A 与该 Bot 的私聊中发送命令。

预期：

- 绑定码有效期显示为 60 至 900 秒范围内的值，默认 300 秒。
- 飞书回复“身份绑定成功”。
- WebUI 的已绑定账号列表在轮询或刷新后出现飞书账号 A。
- 列表显示正确平台、通道、绑定时间和最近活动时间。

### BG-ID-002 英文绑定命令

生成新绑定码，在私聊发送 `bind XXXXXXXX`。

预期：大小写不敏感，绑定成功。

### BG-ID-003 无任务菜单权限的用户绑定

1. 使用账号 B 登录 WebUI。
2. 确认看不到任务指挥中心菜单，但可以打开 Bot 网关。
3. 在 Bot 网关生成绑定码。
4. 使用飞书账号 B 私聊完成绑定。

预期：可以完成绑定，不返回 403，不要求跳转任务指挥中心。

### BG-ID-004 未绑定账号拦截

使用未绑定的飞书账号 C 发送 `帮我查一下今天失败的任务`。

预期：

- 收到“需要绑定身份”及“Bot 网关 → 身份绑定”的准确引导。
- 不创建业务任务。
- 不泄露任何任务标题、编号或状态。

### BG-ID-005 群聊禁止绑定

在群聊发送有效绑定命令。

预期：拒绝绑定，并明确要求在 Bot 私聊完成。

### BG-ID-006 无效、过期和已使用绑定码

分别测试错误码、超过有效期的码、已经绑定过一次的码。

预期：全部拒绝，不改变现有身份映射，提示回到 Bot 网关重新生成。

### BG-ID-007 绑定码通道隔离

1. 在 Bot 网关为飞书通道 A 生成绑定码。
2. 在同一租户的另一个飞书通道 B 私聊中发送该绑定码。
3. 回到通道 A 私聊发送同一个仍在有效期内的绑定码。

预期：通道 B 必须拒绝，且不能消耗该绑定码；通道 A 可以正常完成绑定。绑定码不能只约束平台而忽略具体通道。

### BG-ID-008 账号冲突

尝试把已经绑定给账号 A 的飞书账号绑定给账号 B。

预期：拒绝，不允许一个活动中的外部身份同时映射两个 AOS 用户。

### BG-ID-009 解除绑定

1. 在 Bot 网关“已绑定账号”中点击“解除绑定”。
2. 确认操作。
3. 再从飞书发送任务查询。

预期：

- 列表移除该绑定。
- 后续消息重新要求绑定。
- 原有排队中的主动通知停止投递到该身份。
- 解除 A 的绑定不影响 B。

## 6. 测试发送与收件人

### BG-OUT-001 没有目标会话时测试发送

创建一个没有默认 Chat ID、没有自定义机器人 Webhook、也没有任何入站消息的新通道，点击“测试发送”。

预期：返回明确的缺少 `chat_id`/默认收件人错误，不显示笼统 500。

### BG-OUT-002 复用最近私聊

完成一次私聊入站或身份绑定后，再点击“测试发送”。

预期：测试消息发送到该通道最近记录的会话，消息日志为 `sent`。

### BG-OUT-003 默认 Chat ID

填写合法的默认飞书 Chat ID，在没有最近入站会话的情况下测试发送。

预期：消息发送到指定会话。

### BG-OUT-004 自定义机器人 Webhook

配置合法 Webhook 后测试发送。

预期：无需 OpenAPI 默认 Chat ID 即可发送；Webhook 的实际目标由飞书配置决定。

注意：测试发送证明的是出站消息可达，不代表身份绑定、入站订阅和业务任务执行全部可用。

## 7. 超级助手与 Session 连续性

### BG-SESSION-001 首次消息创建 Bot Session

从已绑定私聊发送：

```text
请记住：本次验收项目代号是北极星，负责人是张三。只回复已记住。
```

预期：

- 创建一个来源为 Bot 的超级助手任务。
- 创建一个超级助手 Session。
- Session 在超级助手会话列表中的名称为 `Bot`，不是 `Session ...` 或 `会话 ...`。
- 飞书先收到受理信息，完成后收到最终结果。

### BG-SESSION-002 同一私聊复用 Session

在同一私聊继续发送：

```text
刚才的项目代号和负责人分别是什么？
```

预期：

- 正确回答“北极星、张三”。
- 两次任务的 `origin_session_id` 相同。
- 第二次执行记录表明 `sessionReused=true`。

### BG-SESSION-003 不同身份隔离

飞书账号 B 询问：

```text
刚才的项目代号和负责人是什么？
```

预期：不得读取账号 A 的上下文；A、B 使用不同 Session。

### BG-SESSION-004 不同会话隔离

同一飞书用户分别在两个不同私聊/会话上下文发送带有不同秘密标记的消息。

预期：两个外部会话不得串上下文，使用不同 Session。

### BG-SESSION-005 Session 结束后轮转

1. 在 WebUI 结束当前 Bot Session。
2. 从原飞书私聊再次发送新问题。

预期：创建新的 Session，新 Session 名称仍为 `Bot`，不复用已完成 Session。

### BG-SESSION-006 上下文压力与自动压缩

在测试环境连续进行多轮长文本、搜索和工具调用，直到触发 Session 压缩。

预期：

- 日志或事件出现 Session compaction 记录。
- 不向用户暴露 `context_window_blocked` 等内部错误。
- 仍复用同一 Session。
- 压缩后继续询问项目代号，核心上下文仍可恢复。
- 精确历史可通过归档能力保留，不应静默丢弃整轮结果。

### BG-SESSION-007 同一会话连续快速发送

在前一轮仍运行时快速发送第二条消息。

预期：同一 Session 的 Turn 被安全串行化或明确排队，不发生状态损坏、结果串线或重复执行。

## 8. 能力路由

### BG-ROUTE-001 无前缀进入超级助手

发送：`北京未来三天天气和出行建议`。

预期：未命中显式前缀时进入超级助手，并按当前搜索配置完成回答。

### BG-ROUTE-002 超级助手斜杠能力

依次测试：

```text
/深度研究 评估 SQLite 作为单机开源产品主数据库的优缺点
/超级对抗 比较 React Query 和 Redux 在本项目中的职责边界
```

预期：

- 命令正确进入对应能力。
- 空命令如 `/深度研究` 被明确拒绝并要求补充任务描述。
- 最终结果回到原私聊。

### BG-ROUTE-003 超级对抗模型前置校验

只启用一个可用模型后发送超级对抗命令。

预期：立即以中英文可理解文案提示至少需要两个不同模型，不进入搜索或重试循环。

### BG-ROUTE-004 数据探索

前提：机器人绑定数据探索能力，并配置测试数据源和查询权限。

测试问题、澄清、SQL 展示、执行结果、无权限表、余额不足和追问分组场景。

预期：

- 澄清内容在会话中可见并进入后续上下文。
- SQL 在执行失败时仍可见。
- 权限错误指出相关表或字段。
- Bot 身份沿用绑定 AOS 用户的数据权限，不使用机器人创建者权限。

### BG-ROUTE-005 代码开发

前提：绑定代码开发能力、测试仓库和 Coding Agent。

发送一个只修改测试文件的小任务。

预期：创建真实研发任务和隔离工作区；完成后返回任务编号、摘要和可访问产物；取消时底层进程停止。

### BG-ROUTE-006 附件

分别从平台发送图片、PDF/文本附件和不支持的超大文件。

预期：

- 合法附件只进入当前绑定用户和当前 Session 的工作区。
- 模型可以读取已支持附件。
- 超限或非法 URL 被明确拒绝。
- 日志不打印带签名的下载 URL、Token 或附件敏感内容。

## 9. 自然语言任务查询与控制

### BG-TASK-001 查询自己的任务

依次发送：

```text
现在有哪些任务在运行？
今天失败的任务有哪些？
刚才那个研究任务进展到哪里了？
研发任务为什么卡住？
```

预期：能识别自然语言和相对指代，不强制要求任务编号；结果只包含本人或已共享任务。

### BG-TASK-002 稳定任务编号

发送：

```text
查看 #任务短编号
停止 #任务短编号
```

预期：准确定位任务；无权限时返回“不可访问”而不是泄露任务详情。

### BG-TASK-003 取消真正终止执行

1. 发起一个会持续调用模型、搜索或工具的长任务。
2. 等待进入运行状态。
3. 发送“停掉刚才那个研究任务”。

预期：

- 收到取消已提交和最终取消状态。
- AgentOps/任务中心变为 `cancelling` 后进入 `cancelled`。
- 底层模型流、工具进程和子任务停止。
- 取消完成后不再产生新的模型调用和工具日志。
- 不发送“任务已完成”的错误通知。

### BG-TASK-004 补充输入

让任务进入 `waiting_input`，然后通过 Bot 补充信息。

预期：补充内容归属于正确任务，任务恢复执行，不再残留虚假的“待我处理”。

### BG-TASK-005 等待审批

触发一个需要确认的值守动作，通过 Bot 批准或拒绝。

预期：只有任务所有者或具备控制权限的用户可以操作；重复审批具有幂等结果。

### BG-TASK-006 普通用户隔离

账号 A、B 各自创建任务；双方查询列表、相对任务和对方短编号。

预期：默认互相不可见；显式共享后按 `read` 或 `control` 权限生效。

### BG-TASK-007 管理员当前边界

管理员从 WebUI 使用租户范围确认可看到租户任务，再从 Bot 查询任务。

预期：当前 Bot 仍只显示管理员本人或已共享任务。若产品将来开放租户级 Bot 控制，本用例必须改为显式管理员命令 + 二次确认 + 审计验证。

## 10. 主动通知和值守规则

### BG-NOTIFY-001 标准事件

逐一构造以下事件：

- `task.completed`
- `task.failed`
- `task.waiting_input`
- `task.waiting_approval`
- `task.stalled`
- `task.cancelled`

预期：只推送通道中勾选的事件；每个事件只投递一次；通知包含可识别的任务标题/短编号和状态。

### BG-NOTIFY-002 未勾选事件

取消勾选 `task.completed` 后完成任务。

预期：不主动推送完成事件，但用户仍能通过 Bot 查询任务，入站问答不受影响。

### BG-NOTIFY-003 通知归属

A、B 都绑定同一通道，各自完成任务。

预期：每条通知只发到任务所有者对应的已验证私聊，不广播到其他绑定用户。

### BG-NOTIFY-004 WebUI 消息不是自动镜像

在 WebUI 发起普通短问答。

预期：普通对话内容不会默认逐条镜像到飞书；只有符合配置的任务事件、订阅或值守规则主动推送。

### BG-NOTIFY-005 值守规则可选

不创建任何值守规则，完成入站问答、任务查询和取消测试。

预期：全部可用。然后创建“无进展 10 分钟 → Bot 通知”规则，确认只有匹配条件时发送。

### BG-NOTIFY-006 去重

同一任务同时满足自动通知、任务订阅和值守规则。

预期：相同事件和目标不会在同一秒产生不可解释的重复通知；如确有不同规则，页面和日志能区分来源。

## 11. 队列、幂等与恢复

### BG-QUEUE-001 重复平台事件

使用相同平台消息 ID 重放完全相同的入站事件。

预期：只创建一个业务任务，不重复调用模型或工具。

### BG-QUEUE-002 服务重启

任务处于 `queued` 或安全可恢复阶段时重启 AOS。

预期：陈旧 claim 被回收，任务继续或明确失败；不会永久停留在 `claimed`。

### BG-QUEUE-003 重试上限

制造持续的适配器错误。

预期：达到最大尝试次数后进入死信/失败状态，错误原因可见，不无限重试。

### BG-QUEUE-004 平台暂时不可用

临时阻断出站网络或填入无效凭据。

预期：业务任务状态与通知投递状态分开记录；用户可在消息日志或投递健康中看到失败原因并安全重放。

## 12. 安全测试

### BG-SEC-001 凭据保护

在输入或模型结果中构造测试形式的 API Key、Bearer Token、密码赋值和带凭据 URL。

预期：按数据保护策略脱敏或阻断；日志只记录类别和数量，不记录原值。

### BG-SEC-002 Webhook 鉴权

对通用 Webhook/回调模式分别使用缺失、错误和正确的入口 Secret。

预期：错误请求被拒绝；正确请求进入队列；错误请求不创建业务任务。

### BG-SEC-003 停用用户

停用已经绑定的 AOS 用户，再从其社交账号发送消息。

预期：身份解析失败并要求重新处理，不以已停用用户权限执行任务。

### BG-SEC-004 停用通道和机器人

分别停用通道、停用机器人后发送消息。

预期：不执行任务；页面和日志显示明确禁用状态。

### BG-SEC-005 群聊 mention 规则

启用 `require_mention` 后，在群聊分别发送未 @ Bot 和已 @ Bot 的消息。

预期：未 @ 不执行；已 @ 按配置执行。私聊不强制 @。

## 13. UI/UX 检查

在中文和英文下分别验证：

- 机器人、通道、身份绑定、消息日志四个页签名称完整。
- 新建通道后自动引导到身份绑定，而不是要求用户猜测下一步。
- 身份绑定页可以在手机和桌面宽度使用，长账号、通道名和时间不重叠。
- 禁用通道不能生成有效绑定流程，并有可理解状态。
- 绑定命令可以一键复制，复制内容包含 `绑定 ` 前缀。
- 解除绑定使用“断开/解除”语义，不使用“删除用户”。
- 通道表格窄屏可横向滚动，操作按钮不覆盖字段。
- 第三方平台官方手册链接与当前平台一致。
- 高级 JSON 帮助按钮能打开，示例不包含真实凭据。
- 测试失败信息指出缺少的 App ID、Secret、Webhook、Token 或收件人。

## 15. 消息日志核对

每个端到端用例至少核对一条入站和一条出站日志：

| 字段 | 预期 |
| --- | --- |
| `direction` | 入站为 `inbound`，回复/通知为 `outbound` |
| `platform` | 与通道一致 |
| `channel_id` | 与测试通道一致 |
| `external_user_id` | 入站发送者稳定 ID，不串用户 |
| `external_conversation_id` | 原私聊/会话 ID |
| `queue_status` | 最终为 `succeeded`，失败为可诊断状态 |
| `agent_task_id` | 能跳转或对应真实 AgentOps 任务 |
| `attempt_count` | 正常为 1，重试有合理上限 |
| `last_error` | 成功为空，失败包含可操作原因且无密钥 |

## 16. 发布验收清单

以下项目全部通过后，Bot 网关才达到开源发布标准：

- [ ] 新用户可以只在 Bot 网关完成机器人、通道和个人身份闭环。
- [ ] 只有 Bot 网关读取权限、没有任务中心权限的用户可以绑定自己的账号。
- [ ] 未绑定、冲突、过期、群聊绑定都被安全处理。
- [ ] 绑定码只能由生成时选中的具体通道领取。
- [ ] 同一私聊连续追问复用 Session，Session 名称为 `Bot`。
- [ ] 不同用户和不同会话绝不共享上下文。
- [ ] 上下文压力触发压缩后仍可继续对话。
- [ ] 超级助手、深度研究、超级对抗、数据探索、代码开发按发布范围通过。
- [ ] 自然语言任务查询、补充、审批、取消覆盖成功和失败场景。
- [ ] 取消会终止底层模型流、工具和子任务。
- [ ] 六类标准任务通知准确、无重复、无串用户。
- [ ] 服务重启、平台失败、队列重试和死信均可诊断。
- [ ] 中英文 UI、错误提示和绑定引导完整。
- [ ] 日志和出站数据不泄露凭据。
- [ ] 飞书完成真实端到端测试。
- [ ] 其他宣称支持的平台完成真实测试或在发布说明中明确验证状态。
