# AOS 任务指挥中心人工测试指南

版本：1.0  
日期：2026-07-27  
测试入口：`http://localhost:5173/tasks`

## 1. 先理解这个菜单

任务指挥中心不是新建普通任务的入口，而是所有长任务的统一观察和控制面。

任务可以从以下位置产生：

- 超级助手：联网、深度研究、数据归因、超级对抗、NL2SQL 等任务。
- 代码开发：代码分析、修改、测试和运行时任务。
- Bot 网关：钉钉、飞书、企业微信、WhatsApp、Slack 等平台发起的任务。
- 产运任务中心：手动或定时执行的计划任务。
- API 或其他接入 AOS 统一任务协议的执行器。

任务指挥中心负责：

- 查看任务是否正在执行、等待处理、失败或完成。
- 查看真实阶段、最近活动、执行时间线、执行尝试和结果文件。
- 停止、重试、补充信息、批准或拒绝任务。
- 关注任务并接收关键状态通知。
- 从手机 Bot 查询进度和接管任务。
- 配置值守规则、移动跟随和外部身份绑定。

普通短问答可能直接进入历史或不长期占据“我的任务”，这是正常行为。测试实时进度时应使用本文提供的长任务 Prompt。

## 2. 通过标准

每个用例必须同时满足：

1. 页面状态与任务实际状态一致。
2. 操作后后台真实执行，不能只改变前端文案。
3. 刷新或断线后状态能够恢复。
4. 同一操作没有产生重复任务、重复命令或重复通知。
5. 浏览器 Console 没有对应异常，服务端没有 panic 或 ERROR。
6. 其他用户和其他租户无法看到任务标题、正文、ID、结果文件或通知。

严重级别：

| 级别 | 含义                                           | 发布要求           |
| ---- | ---------------------------------------------- | ------------------ |
| P0   | 越权、任务丢失、错误终态、停止无效、重复副作用 | 任意失败均阻断发布 |
| P1   | 核心页面、实时恢复、通知、主要交互异常         | 修复后重新测试     |
| P2   | 文案、次要布局或低频平台兼容问题               | 记录后限期修复     |

## 3. 测试准备

### 3.1 服务与迁移

使用完整 feature 启动：

```bash
cd rust
AOS_WEB_SERVER_FEATURES=full ./scripts/dev_web_server.sh build
AOS_WEB_SERVER_FEATURES=full ./scripts/dev_web_server.sh run
```

数据库应已执行 migration 188-200。启动日志不能出现缺表、缺字段或 `ColumnDecode`。

### 3.2 租户开关

把下方 `YOUR_TENANT_ID` 替换为测试租户 ID，在测试库执行：

```sql
INSERT INTO tenant_agent_features (tenant_id, feature_key, mode)
VALUES
  ('YOUR_TENANT_ID', 'watchdog_control_plane_v2', 'on'),
  ('YOUR_TENANT_ID', 'watchdog_external_identity', 'optional'),
  ('YOUR_TENANT_ID', 'watchdog_notification_outbox', 'on'),
  ('YOUR_TENANT_ID', 'watchdog_mobile_handoff', 'on'),
  ('YOUR_TENANT_ID', 'watchdog_watch_rules', 'on')
ON DUPLICATE KEY UPDATE mode = VALUES(mode);
```

说明：

- `watchdog_control_plane_v2=on`：启用统一任务列表、详情、命令和事件流。
- `watchdog_external_identity=optional`：未绑定 Bot 时仍可使用 WebUI；正式强制绑定测试再改为 `required`。
- `watchdog_notification_outbox=on`：启用持久化通知投递。
- `watchdog_mobile_handoff=on`：启用移动跟随和在线状态心跳。
- `watchdog_watch_rules=on`：启用值守规则和决策收件箱。

真实外部通知还要求 `.env` 中设置：

```bash
WATCHDOG_NOTIFICATION_OUTBOX_MODE=on
```

没有真实 Bot 时可以保持 `shadow`，但通知到达手机的用例应记为 `BLOCKED`，不能记为通过。

### 3.3 账号和权限

基础测试使用管理员账号，至少具备：

```text

tasks:control
```

隔离测试再准备：

| B    | T1   | `tasks:read`               | 同租户只读和私有隔离 |
| C    | T2   | 管理员                     | 跨租户隔离           |

## 4. 20 分钟最小冒烟测试

第一次测试先完成本节。任一 P0 失败时停止后续测试并保留日志。

### TCC-SMOKE-01 页面和导航

1. 登录后点击左侧“任务指挥中心”。
2. 依次查看“我的任务”“待我处理”“关注中”“历史”“计划任务”“值守设置”。
3. 再点击页面右上角的刷新按钮。

预期：

- 页面显示标题、说明、任务列表和详情区域，不是空白页。
- 不再显示独立 `AgentOps` 菜单。
- 任务指挥中心不显示“计划任务”Tab；计划任务应从对应业务模块管理，其执行实例仍可在这里观察。
- 空列表显示“当前视图没有任务”，接口失败显示明确错误。
- Console 不出现 React Refresh、重复 `createRoot`、404 或未捕获异常。

### TCC-SMOKE-02 创建可观察的长任务

新建超级助手 Session，发送：

```text
/深度研究 调研企业内部部署 AI Agent 时，任务恢复、权限隔离、审计和成本治理应如何设计。至少比较三种实现路径，给出来源、风险和可执行建议。
```

发送后立即打开任务指挥中心。

预期：

- 顶栏时钟图标出现数字提醒。
- “我的任务”出现一条任务，标题与问题相关，并显示稳定短 ID。
- 状态按真实过程变化，例如 `排队中 -> 已接单 -> 执行中 -> 已完成`。
- 最近活动持续变化，不能十分钟只显示一个静态占位文案。
- 如果没有可计算百分比，可以不显示进度条，不能编造百分比或 ETA。
- 同一个问题只有一个根任务，不出现两条相同任务。

### TCC-SMOKE-03 任务详情

点击刚创建的任务。

预期：

- 显示短 ID、状态、能力、敏感级别、阶段、来源、开始时间和更新时间。
- “执行时间线”按时间显示阶段事件，没有重复事件或状态倒退。
- “执行单元”能看到关联资源；“执行尝试”至少有一次 attempt。
- 任务完成后显示结果摘要；有结果文件时可以打开并看到正确内容。
- “打开原会话”回到原超级助手 Session，不新建 Session、不复制问题。

### TCC-SMOKE-04 关注与取消关注

1. 在任务详情点击“关注”。
2. 切换到“关注中”，确认任务存在。
3. 点击“取消关注”，再次查看“关注中”。

预期：关注后只创建一条有效订阅；取消后任务从“关注中”消失，不影响任务本身执行。

### TCC-SMOKE-05 停止任务

重新发送一个长任务：

```text
/深度研究 系统分析全球主流企业 Agent 平台的任务恢复机制、长任务交互和移动端通知设计，并给出详细对比。
```

任务进入“执行中”后，在任务详情点击“停止”并确认。

预期：

- 状态先进入“停止中”，随后收敛到“已停止”。
- 超级助手页面也显示任务已停止。
- 后台不再继续启动新的搜索、模型轮次或子任务。
- 刷新页面后仍是“已停止”，不能恢复为“执行中”。
- “操作审计”出现一条成功或已接受的 `cancel` 命令。

### TCC-SMOKE-06 刷新恢复

在另一个任务执行期间：

1. 刷新 `/tasks`。
2. 切换到其他菜单，等待 20 秒后回来。
3. 临时断网 15 秒，再恢复网络。

预期：任务、详情和时间线恢复；事件不重复；旧状态不能覆盖新状态；任务不会因页面断线被停止。

## 7. 控制命令测试

按钮只应根据服务端 `allowedActions` 出现。没有按钮不一定是 Bug，先检查任务状态和账号权限。

| ID         | 级别 | 操作                          | 预期结果                                    |
| ---------- | ---- | ----------------------------- | ------------------------------------------- |
| TCC-CMD-01 | P0   | 对运行中任务停止              | 后台真实停止并最终进入 cancelled            |
| TCC-CMD-02 | P0   | 连续快速点击两次停止          | 最多一个有效 cancel，不产生重复副作用       |
| TCC-CMD-03 | P0   | 对失败任务点击重试            | 创建新 attempt，原失败 attempt 和错误保留   |
| TCC-CMD-04 | P0   | 连续快速点击两次重试          | 最多一个活动 retry attempt                  |
| TCC-CMD-05 | P0   | 对 waiting_input 任务补充信息 | 恢复原任务和原会话，不创建平行回答          |
| TCC-CMD-06 | P0   | 对 waiting_approval 任务批准  | actor 和命令被审计，原任务继续执行          |
| TCC-CMD-07 | P0   | 对 waiting_approval 任务拒绝  | 任务按执行器能力收敛，拒绝动作可审计        |
| TCC-CMD-08 | P0   | 刷新旧详情后再执行已过期操作  | 服务端拒绝旧 stateVersion，不覆盖新状态     |
| TCC-CMD-09 | P0   | 对已完成任务尝试停止          | 页面不显示停止按钮；直接调用 API 也应被拒绝 |

检查“操作审计”：每次操作应记录命令类型、状态、时间和错误；失败命令不能伪装成功。

## 8. 结果文件和原会话测试

选择会生成报告或代码产物的任务：

1. 打开“结果文件”。
2. 点击查看按钮。
3. 对照原任务结果。
4. 刷新后再次打开。

预期：

- 内容、名称、类型和大小正确。
- 每次读取都重新鉴权。
- 不显示宿主机物理绝对路径或其他用户资源 ID。
- 大文本以安全方式展示，不撑破页面。
- 图片、Markdown、JSON 或文本无法预览时给出明确错误，不显示空白弹窗。

## 9. 值守设置测试

### TCC-SET-01 移动跟随

1. 打开“值守设置”。
2. 开启“移动跟随通知”。
3. 刷新页面确认开关仍开启。
4. 关闭后再次刷新。

预期：设置持久化；页面每 30 秒更新 presence；开关变化不产生重复客户端身份。

### TCC-SET-02 创建通知规则

创建规则：

```text
名称：任务完成通知
事件：任务完成
无进展分钟：10
动作：通知我
```

然后完成一个长任务。

预期：规则显示为启用；只匹配当前用户的任务；相同完成事件不重复产生通知。删除规则后不再触发。

### TCC-SET-03 需要确认的规则

创建：

```text
名称：失败后请求重试
事件：任务失败
动作：自动重试一次
```

预期：该动作需要确认并进入“决策收件箱”；批准只执行一次，拒绝不执行；重复点击不能重复重试。

### TCC-SET-04 通知投递

绑定真实 Bot 后触发一次完成和一次失败通知。

预期：

- 列表显示平台、标题、状态、尝试次数和更新时间。
- `sent` 必须有真实平台发送结果，不能在 shadow 模式假报成功。
- `failed` 可以按权限重新投递。
- `unknown` 表示平台可能收到但本地未保存回执，不能自动重发。

## 10. Bot 和手机接管测试

本节需要先在“Bot 网关”配置至少一个真实平台。

### TCC-BOT-01 身份配对

1. 值守设置中选择平台并生成配对码。
2. 在对应 Bot 私聊中发送该配对码。
3. 回到页面刷新身份列表。

预期：出现正确平台和显示名；同一个配对码只能使用一次；过期码、错误平台和重放都被拒绝。

### TCC-BOT-02 手机查询进度

在 WebUI 发起长任务，然后通过已绑定 Bot 私聊：

```text
现在哪些任务正在执行？分别到哪一步了？
```

继续发送：

```text
#短ID 为什么这么慢？
```

预期：只返回当前用户可见任务；使用真实短 ID、阶段和最近活动；不编造百分比或完成时间。

### TCC-BOT-03 跨端控制

通过 Bot 对指定短 ID 发起停止、补充信息或审批。

预期：危险动作要求确认；WebUI 实时显示命令和状态；手机与网页操作的是同一个任务，而不是新任务。

### TCC-BOT-04 解绑

在值守设置解绑身份后继续通过 Bot 查询。

预期：访问立即失效；不能继续读取私人任务或接收私人通知。

## 12. 重启和故障恢复测试

这些测试只能在独立测试环境执行。

| ID         | 级别 | 操作                        | 预期结果                                       |
| ---------- | ---- | --------------------------- | ---------------------------------------------- |
| TCC-REC-01 | P0   | 运行中重启 web-server       | 任务恢复或明确失败，不重复启动子任务           |
| TCC-REC-02 | P0   | waiting_input 时重启        | 等待状态和已输入上下文保留                     |
| TCC-REC-03 | P0   | cancel 已接受但未完成时重启 | 命令继续收敛，不回到无停止请求的 running       |
| TCC-REC-04 | P0   | 通知 queued 时重启          | 最终发送一次，不丢失、不重复                   |
