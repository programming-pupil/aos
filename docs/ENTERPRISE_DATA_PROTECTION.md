# AOS 企业数据保护、脱敏与安全基线

本文定义 AOS 面向企业部署时的数据保护基线，覆盖超级助手、统一 Workspace、
NL2SQL、数据归因、深度研究、记忆、附件、任务中心和第三方模型调用。

本文同时区分当前代码已经具备的能力、发布候选必须执行的外部验收，以及企业 GA
仍需补齐的治理能力。未闭环的控制项不能出现在产品安全承诺中。

## 1. 安全目标

企业部署必须满足以下不可降级目标：

1. 租户之间、同租户不同用户之间默认不可读取彼此的私人数据。
2. 未经授权的数据不得进入模型请求、搜索索引、embedding、日志、trace、缓存或导出物。
3. SQL 查询结果在进入模型和前端之前应用同一套列级脱敏策略。
4. API Key、数据库密码、访问令牌和私钥不得以明文进入日志、会话、记忆或 artifact。
5. 权限撤销、资源删除和保留期到期后，主数据、索引、缓存和派生物都必须失效或删除。
6. 模型、工具和文档中的提示注入不能扩大用户原有权限，也不能改变服务端安全策略。
7. 每次敏感读取、查询、导出、模型出站和管理员策略变更均可审计。

## 2. 数据流与信任边界

```text
浏览器 / Bot / API
  -> 身份认证与租户上下文
  -> 超级助手父 Agent
     -> 会话原文、摘要、记忆、Workspace 检索
     -> NL2SQL / 数据归因 -> 数据源 -> 脱敏后的结果
     -> Web 搜索 / 第三方模型
     -> 生成物、事件、trace、审计记录
```

必须独立保护的信任边界：

- 用户浏览器与 AOS API。
- AOS 本地 SQLite 主库，以及 AOS 与 MySQL、TiDB、Trino/Presto 等外部 NL2SQL 数据源。
- AOS 与模型、embedding、Web Search、MCP、Hook、Bot 等外部供应商。
- 统一 Workspace 虚拟资源与宿主机文件系统。
- 在线主数据与日志、备份、向量索引、缓存、导出物等派生副本。

身份只能由服务端认证上下文提供。模型生成的 `tenant_id`、`user_id`、路径、
资源 ID 或数据源 ID 均不得直接作为授权依据。

## 3. 数据分级

企业管理员应在启用模型调用前完成以下分级：

| 级别 | 示例 | 默认处理 |
| --- | --- | --- |
| L0 公开 | 公开网页、公开产品文档 | 允许外部模型处理 |
| L1 内部 | 普通业务文档、非敏感 SQL 模板 | 仅允许批准的模型供应商 |
| L2 机密 | 财务、经营指标、未发布代码、用户行为明细 | 最小化、脱敏、审计、禁止公共搜索出站 |
| L3 严格机密 | 密钥、密码、身份证件、支付信息、健康数据、生产凭据 | 默认阻断模型出站和持久化，必须使用专用受控流程 |

数据标签必须跟随原始资源传播到 chunk、embedding、会话引用、SQL 结果、
artifact 和导出物。派生数据的级别不得低于其最高级别来源。

## 4. 当前已具备的控制

### 4.1 统一 Workspace 隔离

当前 Workspace 以认证上下文中的 `tenant_id + user_id + session_id` 解析资源，
工具参数不能覆盖身份。私人上传、历史、项目和生成物在召回前过滤，在读取时
再次鉴权；租户共享资源需要显式发布和授权。虚拟路径拒绝 `..`、反斜杠、NUL、
编码逃逸和物理绝对路径。

Workspace 游标包含 ACL 指纹和资源版本，撤权或版本变化会使旧游标失效。拒绝
响应不返回其他用户的文件名、路径、ID 或授权信息。详细约束见
[`UNIFIED_WORKSPACE_SECURITY.md`](./UNIFIED_WORKSPACE_SECURITY.md)。

Linux 生产环境仅在 Bubblewrap 隔离自检通过时注册 `workspace_execute`；其他环境
不会降级执行宿主机 Shell。

### 4.2 NL2SQL 结果脱敏

当前支持租户管理员配置列级规则：`redact`、`null`、`constant`、`hash`、
`partial` 和 `tokenize`。规则可按数据源、表和列匹配，并在查询结果返回链路应用。
数据源也可配置敏感列模式。

相关实现：

- `rust/crates/web-server/src/routes/nl2sql/masking_rules.rs`
- `rust/crates/web-server/src/routes/nl2sql/result_masking.rs`
- `webui/src/components/nl2sql/MaskingRulesTab.tsx`

新租户会初始化一组默认敏感列规则，但企业管理员仍必须根据本企业 schema 补齐；
当前实现已经移除代码内不可配置的“万能敏感列名单”。

### 4.3 密钥展示与执行环境

API Key 在部分运行日志和管理接口中使用掩码值，运行时进程记录使用
`env_redacted_json`，前端类型约束也明确认证 token 只能返回脱敏形式。
飞书 SDK 默认只记录 warn/error，所有级别在进入 tracing 前都会遮蔽连接 URL 中的
`access_key`、`ticket`、`token`、`secret` 和授权参数。
数据源、模型和 MCP 密钥仍应由部署环境的 Secret Manager 注入，而不是写入仓库、
镜像、任务 prompt 或 Skill 文档。

租户模型和 embedding 配置默认不会借用进程级环境密钥。仅隔离开发环境可显式设置
`AOS_ALLOW_TENANT_MODEL_ENV_FALLBACK=1` 或
`AOS_ALLOW_TENANT_EMBEDDING_ENV_FALLBACK=1`；生产部署不得开启。

### 4.4 可恢复执行与审计基础

超级助手父 turn、工具事件、Workspace 使用、NL2SQL 查询记录和任务事件提供了
审计数据基础。服务重启恢复、取消和事件序列不能绕过原有认证上下文。

这些记录目前是“审计原料”，尚不等同于完整的企业审计产品；见第 5 节。

### 4.5 共享数据保护边界

当前已提供共享敏感数据检测与脱敏模块，并接入以下边界：

- 模型和 embedding 请求、非流式响应及流式增量。
- Web、MCP、RemoteTrigger 和专业子 Agent 工具的输入输出。
- Hook 的环境变量、stdin、stdout、stderr 和进度事件。
- Bot 出站消息、供应商响应和 `bot_message_logs`；凭据命中会阻断外发。
- JSONL session、exact archive、记忆和 PM 任务/工具账本持久化。
- API/数据库错误响应和主要日志字段。

默认始终处理 API Key、Bearer/JWT、私钥、云凭据、带凭据 URL 和密码/token 赋值。
设置 `AOS_DATA_PROTECTION_STRICT_PII=1` 后，还会处理邮箱、手机号和支付卡号。检测报告
只保存类别和数量，不保存命中原文。该全局严格模式是发布候选控制，不替代第 5.1 节
要求的租户级数据标签和策略产品。

### 4.6 前端诊断与供应链边界

生产前端不向浏览器控制台记录响应头、SSE/WebSocket payload、格式错误事件正文或
API 响应数据；需要异常对象的取消、对抗流和 Error Boundary 诊断仅在开发模式启用。
这可以避免用户问题、工具结果和认证元数据被浏览器扩展、共享终端或远程调试会话收集。

前端已移除存在已知漏洞的 `xlsx` 和处于无安全版本窗口的 React Router，分别使用
`write-excel-file` 与 Wouter；Vite、Vitest、ESLint、TypeScript ESLint 和 ECharts 已升级，
并通过 npm 生产依赖及完整依赖审计。该结果只代表当前锁文件在审计时没有已知漏洞，
不替代发布流水线中的持续 SCA、SBOM、许可证、构建来源证明和镜像扫描。

## 5. 开源发布前必须补齐的 P0 控制

### 5.1 统一出站 DLP 网关

当前状态：**共享检测、脱敏及主要边界已接入；租户级策略闭环待实现**。

模型、embedding、外部工具、Hook 和 Bot 已复用同一敏感数据检测实现，响应回流和主要
持久化路径也会再次处理。外部工具和 Bot 对凭据采用阻断策略，模型请求采用脱敏策略。
尚缺的是按租户、数据标签、供应商、区域和用途配置的统一 allow/redact/deny 决策，
以及证件号、企业自定义正则/词典和管理员可查询的策略命中事件。

所有模型、embedding、Web Search、MCP、Hook 和 Bot 出站必须经过同一个服务端
策略层，不能由各业务分支自行决定。网关至少执行：

1. 根据数据标签、租户策略、供应商和用途决定 allow、redact 或 deny。
2. 检测 API Key、JWT、数据库 URL、私钥、云凭据、邮箱、手机号、证件号、银行卡号
   和企业自定义正则/词典。
3. 只发送完成当前任务所需的最小片段，默认不发送完整文件和无关历史。
4. 在出站前生成可审计的策略命中记录，但审计记录本身不保存敏感原文。
5. 响应回流时再次扫描，防止模型或工具把密钥写入正文、日志、记忆或 artifact。

阻断结果必须给用户明确说明哪类策略阻止了操作，并提供管理员可追踪的事件 ID，
但不能在错误信息中回显被阻断的秘密。

### 5.2 日志与 trace 集中脱敏

当前状态：**主要助手链路已集中处理；全产品 trace/APM 门禁仍需闭环**。

模型客户端、工具执行器、Hook/Bot、会话/研究持久化和统一 HTTP 错误层已使用共享
保护器；模型 payload、工具输入输出和业务 prompt 的诊断日志已改为长度、类型、状态
及内部 ID。仍需对所有非助手模块、反向代理、OpenTelemetry/Sentry/APM 和数据库慢
日志做同一套自动化泄漏测试，不能只依赖代码审查。

禁止业务代码直接记录完整 prompt、模型 payload、SQL 结果、HTTP body、请求头、
文件正文、数据库 URL 或异常对象中的 secret。应提供结构化 `Sensitive<T>` /
`Redacted<T>` 类型和唯一日志过滤层，并默认：

- API Key 只显示前缀和末 4 位，密码、token、cookie、私钥完全不显示。
- 用户问题、SQL 和文件片段只记录 Hash、长度、资源 ID 和分类标签。
- 错误链保留类型、阶段、供应商 request ID，不保留原始敏感 payload。
- production 禁止通过 `RUST_LOG` 打开可能输出正文的 debug/trace target。
- OpenTelemetry、Sentry、APM 和反向代理使用同一套字段过滤规则。

需要加入自动化测试：向每条主要链路注入测试密钥，断言应用日志、SQL 慢日志、
trace、事件表和前端错误中均不存在原文。

### 5.3 模型供应商策略

当前状态：**待租户策略闭环**。

每个租户必须配置供应商 allowlist，并记录：部署区域、数据保留期、是否用于训练、
是否支持 zero data retention、子处理方和跨境状态。L2/L3 数据只有在管理员批准且
供应商能力满足策略时才能出站。

请求不得仅因 API Key 可用就自动降级到另一个供应商。failover 前必须重新执行
数据策略；不满足时宁可使用本地模型或给出受限回答。

当前租户运行时已经默认禁止进程环境密钥回退，缺少 embedding 配置时降级为授权范围
内的词法检索。供应商 allowlist、L2/L3 标签传播和 failover 逐次策略复核仍未产品化。

### 5.4 数据源最小权限与行列权限

当前状态：**列级结果脱敏已具备；最小权限和行级策略依赖部署，需产品化校验**。

- 每个数据源使用独立只读账号，禁止 DDL/DML、文件系统和管理员权限。
- 使用 catalog/schema/table allowlist 和 query timeout、scan bytes、row count 限制。
- 用户授权必须参与数据源选择，不能只依赖租户级数据源可见性。
- 企业行级安全策略必须在数据库或受信策略层执行，不能靠模型生成 `WHERE`。
- 脱敏必须发生在结果进入模型、缓存、事件和前端之前。
- 导出权限应高于预览权限，并对批量导出增加审批、水印和审计。

应增加 A/B 用户集成测试，验证 schema、样例值、错误信息、缓存和执行计划均不会
泄露 B 用户无权访问的表或行。

### 5.5 加密与密钥管理

当前状态：**主要依赖部署环境，需提供标准集成**。

- 传输使用 TLS 1.2+；数据库和内部服务证书必须校验，禁止生产环境跳过验证。
- 数据库、对象存储、备份、Workspace 快照和向量库启用静态加密。
- 主密钥位于 KMS/HSM，应用密钥和租户数据密钥使用 envelope encryption。
- API Key、数据源凭据、Bot token、MCP token 存储于 Vault/KMS/云 Secret Manager，
  支持版本、轮换、吊销和访问审计。
- 不允许前端读取完整 secret；编辑时的占位值不能被误写回数据库。
- 开源默认配置不得包含测试 secret，也不得以明文 `.env` 作为生产推荐方案。

### 5.6 保留、删除与派生数据清理

当前状态：**存在软删除和任务数据，但尚无统一生命周期控制器**。

租户应分别配置会话、记忆、附件、SQL 结果、artifact、事件、日志、embedding 和备份
的保留期。删除必须覆盖：

1. 主记录和对象存储原文件。
2. chunk、全文索引、embedding 和结果缓存。
3. exact archive、会话摘要、长期记忆和生成物中的引用或副本。
4. 搜索缓存、Workspace 游标和本地执行快照。
5. 在合规保留期后到期的备份副本。

删除任务必须幂等、可重试、可审计，并提供“已删除、等待备份过期、因法律保留而
冻结”三种可验证状态。仅设置 `deleted_at` 不等同于完成数据删除。

### 5.7 Prompt Injection 与工具防外泄

当前状态：**Workspace 有服务端鉴权；内容级注入防护需加强**。

- 文件、网页、SQL 注释和工具输出一律视为不可信数据，不得覆盖 system policy。
- 模型只能请求声明过的工具；工具再次执行服务端鉴权和参数验证。
- 工具参数禁止携带凭据和物理路径，资源 ID 由服务端解析。
- Web 内容要求域名、下载大小、MIME、重定向和私网地址校验，防 SSRF。
- 对“上传密钥、关闭审计、读取其他用户目录、把数据发往某 URL”等指令做策略阻断。
- 完成门只能验证服务端工具账本，不能相信模型声称“已脱敏”或“已授权”。

安全测试需包含间接提示注入、恶意 SQL 注释、Unicode/编码逃逸、软链接、压缩炸弹、
跨租户资源 ID 猜测和工具结果伪造。

### 5.8 企业审计闭环

当前状态：**事件已存在，统一审计查询和防篡改仍待实现**。

每条敏感操作至少记录：tenant、actor、角色、session/turn、操作类型、资源内部 ID、
策略版本、授权结果、供应商、数据分类、行数/字节数、时间、结果和 correlation ID。
审计事件不保存敏感正文。

管理员策略变更、密钥读取、共享授权、脱敏规则变更、查询执行、导出、删除和失败的
越权尝试必须进入同一审计流。高风险事件应写入不可变/WORM 存储或外部 SIEM，应用
管理员不能修改历史事件。

## 6. Embedding 与记忆专项要求

Embedding 不是匿名化。向量和 metadata 必须继承原文 ACL、分类、保留期和删除状态。

- embedding 前执行出站 DLP 和供应商策略。
- 向量索引必须按 tenant 分区，并在检索条件中先做授权过滤。
- 缓存键包含 tenant、user、ACL/version、模型和内容 Hash。
- 禁止使用跨租户共享向量索引后再在应用层过滤。
- 删除或撤权后同步删除/失效 chunk、向量和查询缓存。
- 自动记忆只保存完成任务真正需要的信息；密钥、身份凭据和大段原文不得进入记忆。
- 用户必须能查看、纠正、禁用和删除自动记忆。

未配置 embedding 模型时应降级到授权范围内的关键词和原文搜索，不能绕过 DLP 自动
选择未经批准的 embedding 供应商。

## 7. 开源默认安全配置

正式开源包建议使用以下 fail-closed 默认值：

- 租户模型和 embedding 必须显式配置；进程环境密钥回退默认关闭。
- Web Search、MCP、Hook 和 Bot 只有管理员配置后才可出站。
- Workspace 私人资源默认仅 owner 可见；`/shared` 默认空。
- `workspace_execute` 默认关闭，仅 Linux 隔离自检通过后可启用。
- 数据源默认只读，查询、行数、扫描量、并发和超时均有限制。
- 模型请求正文和 SQL 结果日志默认关闭。
- 自动记忆默认可见、可删除，并禁止保存 secret。
- 生产环境检测到默认 JWT secret、明文 HTTP、宽权限数据库账号或调试日志时拒绝启动。
- 任何安全策略加载失败时拒绝敏感操作，不以“保证可用性”为由放行原始数据。

生产建议同时设置 `AOS_DATA_PROTECTION_STRICT_PII=1`，但启用前必须用企业真实数据
分类样本验证误报和业务影响；更细粒度的租户策略完成前，不得宣称支持任意 L2/L3 数据
直接发送到第三方供应商。

## 8. 上线验收标准

上线前至少完成以下自动化验证：

1. 同租户 A/B 用户和跨租户 C 用户无法通过路径、搜索、embedding、缓存、事件、
   artifact、错误信息或资源 ID 读取彼此私人数据。
2. 撤权后旧游标、旧缓存、向量命中和直接资源 URL 立即失效。
3. 预置 100+ 秘密/PII 样本，模型请求、日志、trace、记忆、artifact 和前端无原文。
4. 每种列脱敏规则在普通查询、流式查询、NL2SQL、归因、缓存命中和导出中结果一致。
5. Prompt injection 不能修改 ACL、开启网络、读取宿主机或调用未批准供应商。
6. 删除测试能追踪到原文件、chunk、embedding、缓存、artifact 和备份过期状态。
7. 模型供应商故障切换不会把 L2/L3 数据发送给未批准供应商。
8. 所有敏感操作在 SIEM 中存在关联完整、无敏感正文的审计事件。
9. 依赖、镜像和前端构建通过 SCA/SBOM、secret scan、许可证和高危 CVE 门禁。
10. 完成外部渗透测试和恢复演练，并验证审计、密钥轮换和数据删除不会因重启丢失。

## 9. 建议实施顺序

开源前 P0：统一出站 DLP、集中日志脱敏、供应商 allowlist、Secret Manager、删除闭环、
数据源用户授权、fail-closed 默认配置和跨租户自动化测试。

企业 GA 前 P1：KMS envelope encryption、不可变审计/SIEM、审批式导出、客户自管密钥、
区域驻留、法律保留、DSAR 自动化和供应商合规证据管理。

持续 P2：基于行为的异常检测、敏感数据发现、策略模拟、红队数据集和定期恢复演练。

## 10. 当前发布判定

当前代码可判定为 **开源发布候选（RC）**，不能判定为已认证的企业 GA。代码级回归、
macOS 上的 fail-closed 隔离行为、SQLite A/B 用户 Workspace 隔离和原子事件序号已
验证。发布前仍必须在生产同构 Linux 主机验证 Bubblewrap/prlimit，在批准的真实模型和
数据分类策略下执行聚焦 smoke，并轮换所有曾出现在终端、聊天或本地 `.env` 的密钥。

企业 GA 还需要完成：租户级 L2/L3 供应商策略、全产品 100+ 泄漏样本、统一删除控制器、
SIEM/WORM、Secret Manager/KMS、依赖/SBOM/CVE 门禁、渗透测试和恢复演练。180-case
同模型、同工具、同预算的盲评属于效果验收门，按当前发布决策暂未执行，不能据此宣称效果领先。
