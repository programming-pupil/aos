# AOS v0.1.2

本版本聚焦数据探索与数据归因的可靠性，以及长任务和研发方案的可用性。

## 主要改进

- Trino 查询改为按租户用户隔离的并发闸门，同一用户最多 3 个在途请求，不同用户互不阻塞。
- Trino 查询超时、取消、轮询失败或任务丢弃时主动取消远端 query；远端状态不确定时 fail-closed，禁止自动扩散兼容查询。
- Schema Discovery、数据源测试、手动刷新和定时刷新统一使用 Trino 保护路径。
- NL2SQL 与数据归因保留可执行 SQL、失败证据和下钻进度，避免失败后无依据地重复修复或继续提交查询。
- 代码仓库索引与知识检索优先使用内置本地 embedding，远程 embedding 仅在明确配置后作为增强或替代。
- 知识文件导入、研发方案生成和仓库索引的后台状态更明确，支持异步恢复与进度展示。
- 研发方案支持多项目上下文、渐进式草稿确认和后续代码研发方案生成。
- 修复 MCP、技能安全扫描、Markdown 交付、Bot 网关重复通知和长任务交互相关回归。

## 验证

- `cargo test --workspace --all-features`
- `cargo clippy --workspace --all-features`
- WebUI tests, typecheck, i18n check and production build
- SQLite/MySQL connector boundary and documentation source-of-truth checks
- Real Trino read-only smoke test: one `SELECT 1 AS aos_smoke_check`, no retry

## 离线包

GitHub Actions 会在匹配的原生 Runner 上构建并验证 Linux x86_64、Linux ARM64、macOS Intel、macOS Apple Silicon 和 Windows x86_64 包。每个包都带有 SHA-256 校验文件和完整性清单。

# AOS v0.1.2

This release focuses on reliable data exploration and attribution, plus a more usable long-task and engineering-plan workflow.

## Highlights

- Trino requests now use a tenant-and-user scoped concurrency gate. One user can have at most three in-flight requests while different users remain independent.
- Trino queries are cancelled when they time out, are cancelled, fail during polling, or are abandoned. Uncertain remote state fails closed instead of spawning compatibility retries.
- Schema discovery, datasource tests, manual refreshes, and scheduled refreshes share the same guarded Trino path.
- NL2SQL and attribution retain executable SQL, failure evidence, and drill-down progress instead of blindly issuing repair requests after an uncertain failure.
- Repository indexing and knowledge retrieval prefer the bundled local embedding model. Remote embedding is used only when explicitly configured as an enhancement or replacement.
- Background import, engineering-plan generation, and repository indexing expose clearer progress and recovery states.
- Engineering plans support multi-project context, staged draft confirmation, and follow-up code implementation plans.
- MCP, skill security scanning, Markdown delivery, Bot Gateway deduplication, and long-task interaction regressions are covered by tests and fixes.

## Verification

- `cargo clippy --workspace --all-features`
- WebUI tests, typecheck, i18n check, and production build
- SQLite/MySQL connector boundary and documentation source-of-truth checks
- Real Trino read-only smoke test: one `SELECT 1 AS aos_smoke_check`, with no retry

## Offline packages

GitHub Actions builds and verifies native packages for Linux x86_64, Linux ARM64, macOS Intel, macOS Apple Silicon, and Windows x86_64. Each package includes a SHA-256 checksum and an integrity manifest.
