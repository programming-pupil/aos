# AOS 菜单数据归属与隔离审计

更新时间：2026-07-31

## 结论

AOS 当前不是“所有页面都按用户隔离”。它同时存在四种数据作用域：

- **个人独享**：仅创建者本人可见或可操作。
- **个人为主、显式共享**：默认只归本人，可通过任务授权或管理员权限扩大可见范围。
- **租户共享**：同一租户内具有对应菜单权限的员工共享，跨租户隔离。
- **实例共享**：当前进程级环境变量，同一个 AOS 实例中的所有租户共用。

治理中心是**租户共享聚合**，不是员工个人看板。素材工坊目前也是**租户共享**；超级助手会话、研发任务、规格和个人工作区是**个人独享**。

## 菜单逐项审计

| 菜单 | 当前真实作用域 | 主要数据 | 访问与管理边界 |
| --- | --- | --- | --- |
| Dashboard | 租户共享聚合 | 会话数、用户数、API Key、Hook、MCP、Token/成本、告警 | 查询统一带 `tenant_id`；员工看到的是租户整体指标，不是个人指标。 |
| 超级助手 | 个人独享 | `agent_sessions`、消息、记忆、附件、深度研究任务 | 会话接口同时校验 `tenant_id + user_id`；其他员工和租户管理员不能直接读取个人会话正文。 |
| 任务中心 | 个人为主、显式共享 | `agent_tasks`、事件、产物、命令、订阅、值守规则、投递 | 普通员工仅见自己发起/拥有或被 grant 的任务；根任务授权覆盖子任务；`tasks:admin` 可看租户任务。值守规则、IM 身份绑定、投递列表默认按用户隔离。 |
| 代码开发 | 个人独享任务；仓库索引部分租户复用 | `rd_tasks`、文件变更、测试、运行事件、仓库索引 | 任务查询带 `tenant_id + user_id`；仓库符号/Embedding 索引按租户和仓库复用，不包含个人对话正文。 |
| 规格驱动 | 个人独享 | `rd_specs`、规格阶段、审批、关联任务 | 所有读写校验 `tenant_id + user_id`。 |
| 产运任务 | 租户共享 | PM mission、运行记录、结果 | 页面和接口按 `tenant_id` 查询；具有菜单权限的员工共享。任务进入统一任务中心后，控制权限仍按任务 owner/grant 判断。 |
| 素材工坊 | 租户共享 | `pm_material_jobs`、`pm_material_assets`、素材版本线程 | 当前列表与删除只按 `tenant_id`，`created_by` 仅用于审计，不用于可见性过滤。同租户有菜单权限的员工可查看素材内容。 |
| 治理中心 | 租户共享聚合 | PM 运行、质量门、联网健康、失败、成本、覆盖告警 | 全部指标按 `tenant_id` 聚合；不展示个人私有会话正文。预算档位是租户配置。 |
| 项目 | 个人独享 | GitLab/Git 项目连接与列表 | 项目管理器调用同时传入 `tenant_id + user_id`，不同员工可配置各自项目凭据和项目集合。 |
| Pipeline | 个人独享 | 研发任务、Diff、测试、审批、回滚 | 复用 `rd_tasks`，列表和详情均校验 `tenant_id + user_id`。 |
| 研发质量 | 个人独享统计 | 当前员工的研发任务、变更、测试和模型质量指标 | 聚合 SQL 同时限制 `tenant_id + task.user_id`。 |
| Agent 市场/研发 Agents | 租户共享配置 | Agent profile、workflow、steering rules | 配置、安装状态和规则按 `tenant_id` 共享；使用这些 Agent 产生的具体研发任务仍归个人。 |
| 数据探索 | 个人查询历史；租户数据资产 | NL2SQL 会话、查询、结果、反馈；数据源 schema | 对话和查询历史按 `tenant_id + user_id`；数据源访问还经过角色/数据源 ACL；不得把他人查询历史当租户共享。 |
| 数据源 | 租户共享、受 ACL 控制 | 数据源连接、schema、语义索引、刷新任务 | 资源按 `tenant_id` 保存，普通员工是否可用由数据源访问校验决定；管理员管理租户数据源。 |
| SQL 知识库 | 租户共享、受数据源 ACL 控制 | SQL 示例、术语、语义、Golden Case、索引 profile | 知识用于租户内召回；写入记录保留 `created_by`，但不是个人知识库。 |
| NL2SQL 高级配置 | 租户共享 | domain、synonym、规则、Prompt、脱敏规则、Embedding profile | 由管理权限控制，按租户及数据源隔离。 |
| NL2SQL 分析 | 租户共享聚合 | 查询质量、成功率、反馈、耗时统计 | 面向租户治理；个人会话正文仍由查询接口按用户保护。 |
| Hooks | 租户共享 | `tenant_hooks`、执行日志 | 全部 CRUD 和日志查询带 `tenant_id`。Hook Secret 对有管理权限的租户管理员可见/更新。 |
| Skill 市场 | 租户共享 | Skill 注册表、仓库、安装与扫描状态 | Skill 和仓库按 `tenant_id`；GitHub Token 是实例级运行环境密钥，不写入租户表。 |
| 联网 / Provider | 租户共享 | 搜索 Provider、优先级、健康状态 | 配置与健康状态按 `tenant_id`；Provider Secret 只在管理接口中脱敏返回。 |
| MCP 服务 | 租户共享 | MCP Server、认证信息、连接健康、工具列表 | 注册与读写按 `tenant_id`；同租户会话可选择启用的 MCP。 |
| 工作区 | 个人独享，支持管理员显式发布共享 | 用户文件、上传索引、会话产物；共享 workspace entry/grant | 文件路径解析到当前用户隔离目录。只有管理员可把指定资源发布到租户共享工作区，并通过 grant 指定员工。 |
| API Keys | 租户共享配置 | 模型/API Provider 密钥与模型设置 | 按 `tenant_id`；有 API Key 管理权限的员工共同管理，普通使用者不应获得明文密钥。 |
| 配置管理 | 环境项实例共享；预算项租户共享 | 运行环境变量、`pm_budget_profiles` | `std::env` 修改立即影响整个 AOS 进程，不是租户私有，重启后不持久；深度研究预算保存到当前租户表。仅管理员可修改。 |
| Bot 网关 | 租户共享配置与日志；身份绑定个人 | Bot、Channel、消息日志、能力、外部身份映射 | Bot/Channel/日志按 `tenant_id`；外部 IM 身份绑定到具体 `user_id`，由此继承该员工的任务和会话权限。 |
| 用户管理 | 租户共享管理数据 | 用户、角色、菜单权限、邀请 | 仅租户管理员使用；所有操作限制当前 `tenant_id`。 |
| 通知中心（顶部） | 个人为主，少量租户广播 | `notifications` | 任务/数据源通知通常写入具体 `user_id`；后台语义索引完成事件仍可能写成租户广播。列表会合并同秒同内容重复项，个人不能修改或删除其他用户通知。 |

## 已核对的隔离实现

- 超级助手会话：`agent_session_api.rs` 的列表、详情、消息、删除、重命名都校验会话所属用户和租户。
- 任务中心：`task_control.rs` 的 own scope 使用 owner、initiator 和 `agent_task_grants`；管理员租户视图单独受 `tasks:admin` 控制。
- 研发任务、规格、质量：分别在 `rd/tasks.rs`、`rd/specs.rs`、`rd/quality.rs` 使用 `tenant_id + user_id`。
- NL2SQL 会话和查询：`nl2sql/conversations.rs`、`nl2sql/queries.rs` 使用 `tenant_id + user_id`；共享知识与数据源另走 ACL。
- 工作区：`personal_workspace.rs` 将文件系统根目录解析到用户隔离空间；`unified_workspace.rs` 的共享发布要求管理员并写入 grant。
- 租户配置页：Hook、Skill、MCP、Search Provider、Bot、用户管理的读写都带 `tenant_id`。
- 通知：本轮已补上 mark/delete 的用户作用域，并对同秒同标题、正文、级别的重复通知按组展示和处理。

## 开源前的数据归属建议

当前实现可以开源，但产品文档应明确以下边界：

1. 素材工坊是团队素材库。同租户员工可能看到他人生成文案；若目标是私人草稿箱，需要后续新增 owner/grant，而不是只在前端隐藏。
2. 治理中心、Dashboard、NL2SQL 分析是租户级治理数据。不要在文案中称为“我的成本”或“我的失败率”。
3. 配置管理的环境变量是单实例全局配置。多租户部署时，一个租户管理员不应获得该菜单；AOS 当前单机单组织部署模型下可以接受。
4. Bot 网关日志是租户共享运维数据，但通过 IM 发起的超级助手正文仍应遵守绑定用户的会话权限。
5. 租户广播通知目前共享已读状态；需要严格的“每位员工独立已读”时，应新增广播通知回执表，不能继续直接更新广播主记录。
